# Internationalisation

Two independent translation surfaces:

| Surface | Audience | Where the strings live | Languages |
|---|---|---|---|
| Dashboard | the operator | `services/dashboard/i18n/locales/{en,it}.json` | English, Italian |
| Consent banner | the site's visitors | the site's consent configuration in the database, per locale | any, configured per site |

The backend is not translated: API messages (`title`, `detail`, validation messages) are English and
identified by a stable `code` the client maps to its own strings — see
[../api/errors.md](../api/errors.md).

## Dashboard

`@nuxtjs/i18n` with `strategy: 'no_prefix'` (no `/it/` URL prefix), `defaultLocale: 'en'`, lazy JSON
files in `i18n/locales/`, and browser detection persisted in the `i18n_locale` cookie
(`redirectOn: 'root'`). The user menu has a language switch.

Configured in `services/dashboard/nuxt.config.ts`:

```ts
i18n: {
  strategy: 'no_prefix',
  defaultLocale: 'en',
  langDir: 'locales',
  locales: [
    { code: 'en', language: 'en-US', name: 'English', file: 'en.json' },
    { code: 'it', language: 'it-IT', name: 'Italiano', file: 'it.json' }
  ],
  detectBrowserLanguage: { useCookie: true, cookieKey: 'i18n_locale', redirectOn: 'root' }
}
```

### Using it

```vue
<script setup lang="ts">
const { t } = useI18n()
</script>

<template>
  <h1>{{ t('overview.title') }}</h1>
  <p>{{ t('report.rows', { count: total }) }}</p>
</template>
```

No raw user-visible text in a component. Nuxt UI's own strings follow the active locale.

### Key structure

Keys are nested and grouped by area. The top-level groups are:

```
app  nav  common  errors  validation  periods  intervals  compare  metrics  columns
filters  availability  report  overview  pages  sources  campaigns  audience  events
goals  funnels  attribution  retention  realtime  sites  site  settings  consent
security  auth  user  roles  users  jobs  admin
```

Conventions:

- one key per concept, named after the concept, not after the sentence — `metrics.bounceRate`, not
  `theBounceRateIs`;
- reuse `common.*` for save/cancel/delete and `errors.*` for API error codes rather than repeating
  them per page;
- no string concatenation for sentences; use interpolation and pluralisation.

### Parity is enforced

```sh
cd services/dashboard && pnpm i18n:check
```

`scripts/i18n-check.mjs` flattens every locale file and fails when any file is missing a key that
another has, naming the missing keys. Adding a key to `en.json` without adding it to `it.json` fails.
It runs as part of the dashboard checks.

### Adding a language

1. Add `i18n/locales/<code>.json` with **every** key (copy `en.json` and translate).
2. Add the locale to `nuxt.config.ts`.
3. `pnpm i18n:check` and `pnpm test`.

Nothing else is language-aware.

## Formatting

Numbers, dates and currency use `Intl` through `app/composables/useFormatters.ts`, with:

- the **active locale** for the number and date format;
- the **site's time zone** (`meta.timezone` from the API) for dates, never the browser's — a report for
  "2026-09-17" means that day in the site's time zone;
- the **site's currency** (`meta.currency`) for money, which the API returns in **minor units**
  (`revenue_minor`, `value_minor`, `amount_minor`), so divide by 100 (or by the currency's exponent)
  at the presentation layer only.

Durations are milliseconds (`avg_duration_ms`, `avg_engagement_ms`); rates are fractions
(`bounce_rate: 0.6667`), formatted as percentages.

## Consent banner

Banner texts are **not** part of the dashboard's translations: they are data, edited per site and
published as an immutable revision. Each locale needs `title`, `body`, `accept`, `reject`, `close`,
`policy` and `reopen`, plus a `policy_urls` entry.

At runtime the tracker picks the language from `<html lang>` (primary subtag), falls back to the
configuration's `default_locale`, and then to the first locale that has texts. Locale codes look like
`en` or `pt-BR`.

English and Italian defaults ship in `ConsentService::defaults()`; they are a starting point, not
legal text — see [../privacy/legal-review-points.md](../privacy/legal-review-points.md) (LR-7).

Editing: [../integration/consent-banner.md](../integration/consent-banner.md).

## Console and logs

`bin/analytics`, its output, the log messages and the audit log actions are English only, and are not
translatable. They are operator-facing and are matched by scripts.

## Checklist for a change

- [ ] No literal user-visible string in a Vue component
- [ ] The key added to **every** locale file
- [ ] `pnpm i18n:check` passes
- [ ] Dates formatted in the site's time zone, money in minor units with the site's currency
- [ ] A new consent text key added to `ConsentService::TEXT_KEYS`, the tracker's `Texts` interface and
      the banner template together
